# Windows 源码双击启动

下载 ClipForge 源码后，双击项目根目录的 `start.cmd`，即可在本机浏览器使用网页版。无需安装 Electron 桌面版，也无需管理员权限。

## 使用步骤

1. 从 GitHub 克隆项目，或通过 **Code → Download ZIP** 下载并完整解压。不要直接在压缩包内运行脚本。
2. 双击根目录的 **`start.cmd`**。首次需要联网下载运行环境、依赖及媒体工具，并执行生产构建，可能耗时数分钟，请保持控制台打开。
3. 等待脚本确认服务就绪，浏览器会自动打开 **`http://127.0.0.1:3000/settings`**。
4. 在设置中启用 **Kling 官方 CLI**，保存预填的本机路径并检测环境，完成官方登录，再选择默认视频模型。如需 ElevenLabs，在 **设置 → 配音** 选择并开启它，完成 OAuth 登录后选择声音和模型。启动本身不会自动登录，也不会提交生成或产生生成扣费。
5. 使用期间保留控制台窗口。结束时在控制台按 **Ctrl+C** 停止本机服务。

关闭浏览器不会停止服务。再次双击时，如果同一项目的服务已经运行，脚本会打开已有服务。默认使用 `127.0.0.1:3000`，便于保留同一浏览器来源下的设置；端口冲突时会提示处理，不会自动切到另一个端口。

## 自动准备的内容

| 内容 | 处理方式 |
| --- | --- |
| Node.js | 优先复用系统 x64 Node 22.13+ 或 Node 24 LTS；否则从 Node.js 官方下载最新的便携 x64 Node 22，并按官方 SHA-256 校验文件核对下载内容 |
| pnpm | 使用项目 `package.json` 的 `packageManager` 固定版本，本地准备，无需全局安装 |
| 项目依赖 | 按 `pnpm-lock.yaml` 安装；准备数据库与媒体工具依赖 |
| Kling CLI | 项目本地安装固定版本 `@klingai/cli-global@0.2.0`，无需全局安装 |
| ElevenLabs CLI | 检查官方 `@elevenlabs/cli@1.8.0` 及当前平台二进制，缺失或无法运行时在项目本地自动安装；保留 optionalDependencies，无需全局安装 |
| 网页服务 | 首次运行或源码变化后重新构建；就绪后才打开浏览器 |

便携 Node、pnpm、Kling CLI 和 ElevenLabs CLI 放在项目的 **`.clipforge`** 下，运行日志和启动状态也保存在此；此目录已从 Git 排除。ElevenLabs 安装在 `.clipforge/tools/elevenlabs`，每次启动会通过 `--version` 检查，准备成功后复用安装。依赖安装时跳过 Electron 二进制下载，运行网页版不需要它。

CLI 的本地安装与官方账号授权是两步。启动器通过环境变量为设置页预填 Node 与 CLI 路径；进入 **Kling 官方 CLI** 后仍需启用、保存、检测并登录，再到视频生成设置选择默认视频模型。生成、确认计费与恢复操作见 [Kling CLI 本机网页版使用说明](../Kling-CLI本机网页版使用说明.md)。

启动器也会向网页服务传入 ElevenLabs 的本地安装路径；OAuth 复用当前系统用户的账号凭据，不写入工具安装目录。开启配音与登录步骤见 [ElevenLabs CLI 配音](elevenlabs-cli.md)。`--check` 同时检查两个 CLI，仅报告环境状态，不会安装或登录。

## 可选启动参数

在项目目录的终端可使用以下命令：

```powershell
# 只检查现有环境；不安装依赖、不构建
.\start.cmd --check

# 启动服务，但不自动打开浏览器
.\start.cmd --no-browser

# 明确选择其他端口
.\start.cmd --port 3001
```

已安装兼容 Node 时，也可直接执行 `node scripts/launch-local.mjs` 或 `pnpm start:local`，参数相同。`--check` 用于诊断，工具或依赖缺失时返回失败，首次缺少环境时请正常双击启动。显式切换端口会改变浏览器来源，旧端口下的浏览器设置不会自动迁移；建议日常使用固定地址。

根目录的 `start.cmd` 是双击入口，依次调用 `scripts/start-local.ps1` 准备 Node，再调用 `scripts/launch-local.mjs` 安装、构建并启动。请保留这些源码文件；入口不依赖预先安装 Node 或 pnpm。双击启动失败时窗口会暂停显示错误；带参数运行时直接返回退出码，便于终端诊断和自动化。

## 数据与更新

项目、素材、成片、Kling 任务及独立登录凭据默认保存在项目根目录的 **`data`**，启动与重新构建都会保留它。浏览器中的设置还与浏览器及访问地址有关，请持续使用同一浏览器和 `http://127.0.0.1:3000`。

更新前按 Ctrl+C 停止服务，并备份完整 `data` 目录；随后拉取源码，再双击启动。使用 ZIP 更新时，请保留原项目中的完整 `data`。不要只备份数据库或输出视频，Kling 任务恢复还依赖输入快照、凭据和回执。不要把含凭据的数据目录提交到 GitHub。

本脚本用于本机浏览器访问。Kling 接口依赖本机地址与同源会话，不适用于局域网访问或远程多人部署。

## 常见问题

**首次一直在下载或构建？**

查看控制台进度。Node.js 官方下载、npm 包及媒体二进制都需要网络。失败时先根据控制台错误检查网络，再重新双击；首次准备完成后，后续启动会复用已有环境。

**端口 3000 被占用？**

如果占用者是同一项目正在运行的服务，脚本直接打开它；如果是其他程序或另一份项目，请先停止该服务，再运行脚本，也可通过 `--port` 明确指定端口。脚本不会自动结束其他进程或换端口。

**浏览器没有自动打开？**

在控制台确认服务已经就绪后，手动打开 `http://127.0.0.1:3000/settings`。若控制台报错，请先处理该错误。

**Windows ARM64 可以使用吗？**

Windows 11 ARM64 可通过系统的 x64 仿真运行。由于媒体依赖没有完整的 Windows ARM64 原生二进制，启动器会自动准备 x64 Node，并以 x64 安装数据库及媒体工具；不会复用系统 ARM64 Node。没有 x64 仿真支持的系统不在自动启动支持范围内。

**停止后云端生成会取消吗？**

Ctrl+C 停止本机服务和本地处理，不能取消已提交到 Kling 的云端任务。重新启动后从原任务恢复查询或保存；提交结果不明时先核对原任务，不要重复生成。整片计划尚未提交的镜头须按页面要求重新确认恢复。
